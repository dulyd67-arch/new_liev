# LiveStar Web

واجهة Next.js للبث المباشر، بالعربية والإنجليزية، مع تصميم متجاوب للهواتف.

الصفحات المتاحة:

- `/`: البحث في البثوث النشطة وتصفيتها حسب التصنيف.
- `/go-live`: معاينة الكاميرا والميكروفون، ثم بدء بث فعلي أو استعادته وإنهاؤه.
- `/live/[id]`: مشاهدة الصوت والصورة، ومشاركة الرابط، ومحادثة تتحدث تلقائياً.
- `/login` و`/register`: تسجيل الدخول وإنشاء حساب.
- `/forgot-password` و`/reset-password` و`/verify-email`: استعادة الحساب والتحقق من البريد.
- `/settings` و`/u/[username]`: تعديل الملف الشخصي وعرضه.

## التشغيل

من جذر المستودع بعد تشغيل API وقاعدة البيانات وLiveKit وفق الدليل الرئيسي:

```sh
npm ci
npm run dev:web
```

الواجهة على `http://localhost:3000`. يمرر Next.js طلبات `/api/v1` إلى
`API_INTERNAL_URL`، وافتراضياً `http://127.0.0.1:4001/api/v1`.

```sh
npm run typecheck --workspace @livestar/web
npm run build --workspace @livestar/web
npm run start:web
```

يطلب الاستوديو إذن الكاميرا والميكروفون عند ضغط زر تشغيل المعاينة فقط.
يبدأ النشر بعد الضغط على بدء البث. يجب إبقاء صفحة الاستوديو مفتوحة؛
المغادرة توقف الأجهزة وترسل طلب إنهاء البث. رابط المشاهدة يفتح في صفحة مستقلة.
قد يحتاج المشاهد إلى الضغط على تشغيل الصوت بحسب سياسة المتصفح.

الفيديو والصوت عبر `livekit-client` وWebRTC. الرسائل تحفظ في API ويتم تحديثها
كل 2.5 ثانية. تحفظ رموز الوصول في الذاكرة، بينما يستخدم التجديد ملف ارتباط
HttpOnly من الخادم. لا توجد بيانات بث أو مشاهدات أو معاملات مالية مصطنعة.

الكاميرا تعمل محلياً على localhost؛ التشغيل على نطاق عام يتطلب HTTPS وWSS
وعنوان LiveKit متاحاً للمشاهدين، مع ضبط أصل الواجهة المسموح في الخادم.

## التحقق

نجح بناء Next.js وفحص TypeScript. تحقق اختبار متصفحين لدى المشروع من وصول
إطارات فيديو وصوت عبر خادم LiveKit فعلي، وإرسال المحادثة، وعدّ المشاهدين
من مشاركي الخادم، وتوافق عرض الهاتف، وإنهاء البث. الكاميرا والميكروفون في
الاختبار أجهزة Chromium اصطناعية مخصصة للاختبارات، وليسا مستخدمين حقيقيين.
