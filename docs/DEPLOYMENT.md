# تشغيل LiveStar ومتطلبات النشر

## ما يمكن تشغيله الآن

الخادم NestJS وPostgreSQL وRedis مع ترحيلات وإعدادات مرجعية، ومصادقة وإدارة
حساب وملف شخصي واستعادة بريد تعمل عبر SMTP. واجهات Next.js وFlutter في
المرحلة الثالثة قيد التنفيذ ولم تُقبل بعد. لا يوجد تكامل تطبيقي للبث أو
التخزين أو المدفوعات؛ أدلة المتاجر والإنتاج الكاملة تتبع تنفيذ تلك المكونات.

أصبحت بيئة التطوير قادرة على الوصول إلى Docker والشبكة. شُغّل PostgreSQL
وRedis داخل Compose، وطُبّقت الترحيلات واختبارات التكامل، وشُغّل API المبني
على المضيف مع فحص فشل Redis وتعافيه. اجتاز أساس المرحلتين الأولى والثانية
التحقق، بما فيه دورة هوية فعلية مع Mailpit. نجحت أوامر بناء API داخل Docker،
وتعطل إنهاء الصورة أولًا عند حد مساحة VFS. عولج ضغط المساحة محليًا، لكن
الصورة النهائية وتشغيلها غير متحققين بعد. التفاصيل في
[سجل المرحلة الأولى](PHASE1-VALIDATION.md) و[سجل المرحلة الثانية](PHASE2-VALIDATION.md)، وحالة المراحل في
[سجل التقدم](PROGRESS.md).

## تطوير باستخدام Node على المضيف

استخدم Node.js 22.13 أو أحدث ضمن الإصدارين 22 أو 24، وnpm 10 أو أحدث،
وDocker Compose. من جذر المستودع:

```sh
cp .env.example .env
source scripts/env.sh
npm ci
npm run db:generate
docker compose --profile mail up -d postgres redis mailpit
npm run db:deploy
npm run build
npm run dev:api
```

`source scripts/env.sh` يحمّل ملف إعداد محليًا موثوقًا، لذا لا تستخدم ملف `.env`
مرسلًا من مصدر غير موثوق. لا تحفظ `.env` أو أسرار المزود في Git.

`DATABASE_URL` اتصال `livestar_app` المحدود على المضيف.
`DATABASE_MIGRATION_URL` اتصال `livestar_owner` المستخدم للترحيل والتهيئة.
يجب تشفير أحرف كلمة المرور الخاصة داخل URL. `REDIS_URL` اتصال Redis،
و`WEB_ORIGIN` قائمة أصول مسموحة مفصولة بفواصل. مع تغيير المنفذ المحلي عدّل
متغير المنفذ وURL المقابل معًا.

`JWT_SECRET` في الأمثلة مفتاح تطوير محلي؛ الإنتاج يحتاج قيمة عشوائية فريدة
لا تقل عن 32 بايت. يحدد `APP_PUBLIC_URL` أصل روابط البريد، ويجب أن يستخدم
HTTPS في الإنتاج. `SMTP_HOST/SMTP_PORT/SMTP_FROM` تضبط البريد، ومع المصادقة
تُضاف `SMTP_USER/SMTP_PASSWORD` معًا. Mailpit يلتقط رسائل SMTP المحلية على
1025 وتعرضها واجهته على `http://localhost:8025`؛ لا يثبت ذلك تسليم بريد خارجي.

في طرفية ثانية بعد تحميل البيئة:

```sh
curl --fail http://localhost:4000/api/v1/health/live
curl --fail http://localhost:4000/api/v1/health/ready
curl --fail http://localhost:4000/api/v1/platform
npm run check
```

الخادم يستمع افتراضيًا على المنفذ 4000. فحص الجاهزية يعيد 503 عند انقطاع
PostgreSQL أو Redis. `/api/docs` و`/api/openapi.json` يصفان المسارات المنفذة فقط.
اختبارات قاعدة البيانات `npm run db:test` مخصصة لقاعدة اختبار معزولة؛ راجع
[سجل المرحلة الثانية](PHASE2-VALIDATION.md) قبل تشغيلها. اختبار
`npm run test:auth:integration` يحتاج Mailpit ويختبر دورة هوية فعلية على
قاعدة اختبار معزولة، دون إرسال رسائل إلى مزود خارجي.

## تطوير داخل Docker

الأوامر التالية مسار التشغيل المستهدف للصورة. يجب إكمال بنائها وتشغيلها على
بيئة ذات مساحة كافية قبل الاعتماد عليها. فشلت محاولة سابقة عند إنهاء الصورة
بسبب `no space left on device`، رغم نجاح أوامر البناء داخلها. عولج ضغط
المساحة المحلي؛ نجاح إعادة بناء الصورة وتشغيلها ما زال يحتاج تحققًا فعليًا.

```sh
cp .env.example .env
docker compose --profile app --profile mail up --build -d
docker compose logs --tail=100 migrate api
curl --fail http://localhost:4000/api/v1/health/ready
```

خدمة `migrate` تعمل بهوية المالك وتنتهي، ثم تبدأ API بهوية التطبيق دون سر المالك.
تشغّل الخدمة `npm run db:deploy` الذي يطبق الترحيلات والتهيئة المرجعية
تلقائيًا، لضمان وجود دور USER اللازم للتسجيل. Prisma و`tsx` تبعيات تشغيل
لحزمة قاعدة البيانات في هذه الصورة المشتركة. لا توجد حسابات مستخدمين أو
كلمات مرور افتراضية. ملفات الترحيل تطبق بالترتيب ولا تعدّل
بعد نشرها؛ التغييرات اللاحقة بترحيلات جديدة واختبار على نسخة بيانات مناسبة.

الأوامر الاختيارية:

```sh
docker compose --profile app --profile gateway up -d
docker compose --profile storage up -d
docker compose --profile media up -d
docker compose --profile mail up -d
docker compose --profile app --profile mail --profile storage --profile media --profile gateway config --quiet
```

Nginx المحلي على `http://localhost:8080/api/`، وMailpit على 1025/8025، وMinIO على 9000/9001، وLiveKit
على 7880 و7881 وUDP 50000–50100. جميع المنافذ المنشورة مقيدة بـloopback.
مفاتيح LiveKit ثابتة للتطوير فقط. لا يوجد إصدار media tokens أو رفع ملفات بعد.
تفاصيل البناء مع proxy CA في [دليل البنية التحتية](../infra/README.md).

`docker compose down` يوقف الخدمات مع الاحتفاظ بالبيانات. تغيير متغير كلمة
المرور لا يغير كلمة مرور دور PostgreSQL داخل volume قائمة؛ يلزم تدوير صريح
آمن. لا تستخدم حذف volumes لاستكشاف خلل في قاعدة تحتوي بيانات مطلوبة.

## النشر الإنتاجي لاحقًا

Compose الحالي بيئة تطوير. قبل نشر VPS أو Cloud، استكمل:

1. نطاق DNS وHTTPS بشهادات مجددة آليًا، وWSS للبث والمحادثة، وشبكات خاصة لقواعد البيانات.
2. أسرار فريدة عبر secret manager، وهوية ترحيل منفصلة، واتصال قاعدة بيانات مشفر، وصلاحيات تخزين محدودة.
3. سعة PostgreSQL واتصالاته، ونسخ Redis، وتوزيع LiveKit إقليميًا وTURN واختبار وصول الهواتف عبر NAT.
4. تخزين خاص وروابط ملفات موقعة وسياسات احتفاظ وCDN، مع منع كشف ملفات الهوية.
5. مراقبة وأخطاء منقحة من الأسرار وبيانات الدفع، وإنذارات فشل Webhooks والتسويات والسحب وتأخر Outbox.
6. نسخ احتياطي مشفر خارج المضيف، وWAL/PITR بحسب RPO، وتجربة استعادة وقياس RTO؛ الأدوات الأولية في `infra/backup`.
7. اختبارات أمن وأداء وتحميل بث وفشل دفع واسترداد، وخطة ترحيل واسترجاع إصدار دون فقد معاملات.

ملف CI يتحقق من البناء والاختبارات باستخدام خدمات PostgreSQL وRedis.
لا توجد حاليًا وجهة CD أو نشر تلقائي أو شهادة SSL أو نطاق مربوط.

## اعتماد الدفع والسحب

اختر محول Web بحسب بلد الشركة والمنتج والبلدان المدعومة، ثم وفر أسرار sandbox
والمنتجات وWebhooks الموقعة. في Android/iOS تعتمد المنتجات الرقمية على
Google Play Billing وApple IAP إلا عند انطباق استثناء إقليمي معتمد. لا تستخدم
مفاتيح إنتاج قبل اختبارات الإيصالات والتكرار والفشل والتسوية.

السحب يحتاج مزودًا يدعم بلد المنشئ وحسابه، وKYC وفحوص الأهلية والتعليق
والاحتيال حسب النشاط. لا يكفي وجود حساب Stripe أو PayPal لضمان الإتاحة.
50/50 تطبق على صافي إيراد الهدايا المؤهل وفق [السياسة المحاسبية](ACCOUNTING.md)،
وليست وعدًا بتحويل LiveCoins إلى نقد.

## بناء التطبيقات لاحقًا

`apps/mobile` ضمن عمل المرحلة الثالثة الجاري؛ لم يُقبل بناء APK/AAB/iOS
بعد. أثناء إنشاء Flutter، يثبت إصدار Flutter/Dart وتضاف
معرفات الحزم وإعدادات الكاميرا والميكروفون والإشعارات وdeep links. Android
يحتاج signing keystore محميًا وPlay Console وAAB موقعًا. iOS يحتاج macOS
وXcode وApple Developer وprovisioning وApp Store Connect. المرحلة الثامنة
تضيف أدلة بناء واختبار ونشر مرتبطة بملفات التطبيقات الفعلية وموافقات المتجر.
