# LiveStar — دليل نسخة اللايفات

آخر تحديث: 2026-11-13.

هذه النسخة تركز على رحلة واحدة: يدخل صاحب البث بحسابه، يبدأ الكاميرا
والميكروفون، ثم يشارك رابط المشاهدة. يستطيع الزائر مشاهدة البث، ويستطيع
المستخدم المسجل إرسال رسائل في المحادثة. تتولى Next.js الواجهة، وNestJS
الحسابات والغرف والرسائل، وLiveKit نقل الصوت والصورة عبر WebRTC.

## الحالة الحالية

تم تنفيذ النسخة المبسطة وتشغيلها محليًا. في 2026-11-13 نجح اختبار جلستين
مستقلتين في Chromium عبر الموقع: إنشاء حساب، معاينة الكاميرا والميكروفون،
نشر مساراتهما إلى LiveKit، استقبال إطارات فيديو مفكوكة الترميز ومسار صوت
في جلسة المشاهد، إرسال رسالة وظهورها لدى الناشر، عرض البث وعدد المشاركين
الفعلي، ثم إنهاء الغرفة وتحديث صفحة المشاهد.

أجهزة الكاميرا والميكروفون في الاختبار هي أجهزة Chromium اختبارية، أما نقل
WebRTC وخادم LiveKit وقاعدة البيانات وطلبات HTTP فكانت فعلية. لم يُختبر
بعد الوصول من جهاز خارجي أو شبكة هاتف، ولم يحدث نشر إنتاجي.

نجح بناء Next.js وNestJS وفحص الأنواع، ونجحت 51 حالة اختبار للخادم و24
لقاعدة البيانات و9 فحوص ساكنة. نجح أيضًا اختبار HTTP لإنشاء غرفة فعلية
ومنع نشرها دون مسارات ومنع غير مالكها من إدارتها وحذفها فعليًا عند الإنهاء.
سجل قبول المتصفح: `artifacts/live-browser-result.json`؛ وصور الواجهة في
`artifacts/live-studio.png` و`artifacts/live-watch.png` و`artifacts/live-mobile.png`.

استخدم LiveKit Server **1.13.11** مع عميل JavaScript **2.24.0** كما في
ملفات Compose وlockfile. الإصدار القديم 1.8.4 تعثر عند نشر الفيديو مع
العميل الحالي؛ نجح التدفق نفسه بعد تحديث الخادم، دون محاكاة نجاح النشر.

## تجربة البث محليًا

اتبع خطوات [README](../README.md)، ثم:

1. افتح الموقع على `http://localhost:3000` وأنشئ حسابًا أو سجّل الدخول.
2. اختر **ابدأ بثًا**، واكتب العنوان، ثم شغّل معاينة الكاميرا والميكروفون.
3. وافق على صلاحيات المتصفح، وابدأ البث بعد ظهور المعاينة.
4. انسخ رابط المشاهدة وافتحه في ملف متصفح آخر على الجهاز نفسه. بذلك تكون
   جلسة المشاهد مستقلة عن جلسة صاحب البث.
5. سجّل الدخول في جلسة المشاهد لاختبار إرسال رسالة وظهورها في المحادثة.
6. أنهِ البث من جلسة صاحبه، وتحقق من توقف الصوت والصورة وتحديث صفحة المشاهد.

الصوت قد يحتاج نقرة من المشاهد وفق سياسة التشغيل التلقائي للمتصفح. أغلق
معاينة الكاميرا أو البث عند الانتهاء لتحرير الكاميرا والميكروفون.

## العناوين والمتغيرات

| المتغير أو العنوان | الاستخدام المحلي |
| --- | --- |
| الموقع | `http://localhost:3000` |
| API | `http://localhost:4001/api/v1` |
| `API_INTERNAL_URL` | عنوان API الذي يستخدمه خادم Next.js للتمرير الداخلي |
| `LIVEKIT_URL` | عنوان WebSocket الذي يتصل به متصفح الناشر والمشاهد |
| `LIVEKIT_API_URL` | عنوان إدارة الغرف الذي يستخدمه NestJS فقط |
| `LIVEKIT_API_KEY` و`LIVEKIT_API_SECRET` | مفاتيح خادم الوسائط؛ قيم المثال للتطوير المحلي |
| `WEB_ORIGIN` | أصول الموقع المسموح بها للمصادقة |
| `APP_PUBLIC_URL` | أصل روابط الموقع ورسائل الحساب |
| Mailpit | `http://localhost:8025` لقراءة رسائل التطوير |

يعرض المتصفح رابطًا نسبيًا لـAPI عبر `/api/v1`؛ يحتفظ الخادم بمفتاح LiveKit
السري. صلاحية الناشر مرتبطة بصاحب الغرفة، ورمز المشاهد يسمح بالاشتراك فقط.
المحادثة تحفظ في PostgreSQL وتُحدَّث بطلبات دورية كل 2.5 ثانية.

إعداد LiveKit المرفق يعلن عنوان loopback للتجربة على جهاز واحد. عنوان
`127.0.0.1` يشير دائمًا إلى الجهاز الذي يشغّل المتصفح؛ لذلك يحتاج الاختبار
من جهاز آخر إلى عنوان خادم وسائط خارجي صحيح، وليس نسخ عنوان التطوير كما هو.

## فحص قبول النسخة المبسطة

تحققت الحالات التالية ضمن الاختبارات المذكورة:

- يعمل التسجيل والدخول، وتُحفظ جلسة المتصفح دون وضع رمز التحديث في بيانات الواجهة.
- لا تظهر غرفة ضمن البثوث المباشرة قبل اتصال ناشر فعلي ونشره مسار صوت أو فيديو.
- ينجح استقبال الصوت والصورة في جلسة مشاهد منفصلة، وتبقى صلاحيتها للمشاهدة فقط.
- تُحفظ رسالة المستخدم وتظهر في المحادثة كنص.
- يمنع الخادم مستخدمًا آخر من الحصول على رمز نشر الغرفة أو إنهاء بث صاحبها.
- يوقف إنهاء البث الغرفة الفعلية في LiveKit، ثم يحدّث حالتها في قاعدة البيانات.

توجد في الواجهة معالجة لانقطاع الخدمة ورفض إذن الكاميرا وتحرير المسارات؛
اختبار المتصفحين المذكور غطى السماح بالكاميرا وإنهاء البث، ولا يمثل اختبارًا
على كل جهاز أو إعداد صلاحيات متصفح.

لإعادة اختبارات التكامل استخدم قاعدة اختبار معزولة، وشغّل API والموقع
وLiveKit وMailpit، ثم حمّل `.env.test.example`:

```sh
set -a
source .env.test.example
set +a
npm run test:live:integration
npm run test:live:browser
```

اختبار المتصفح يحتاج Chromium. يستخدم `/usr/bin/chromium` إن كان مثبتًا،
أو متصفح Playwright المثبت عبر `npx playwright install chromium`؛ يمكن تحديد
مسار آخر عبر `CHROMIUM_PATH`. ترفض اختبارات التكامل العمل على قاعدة لا
يحتوي اسمها `test`، وتضيف حسابات اختبار معلّمة داخلها.

## النشر على خادم

ملفات البيئة وCompose الحالية موجهة للتطوير. للنشر جهّز نطاق الموقع وHTTPS،
وعنوان LiveKit عامًا مع WSS وعنوان ICE صحيح وإعداد TURN وفق الشبكة،
والمنافذ اللازمة للوسائط. اضبط `WEB_ORIGIN` و`APP_PUBLIC_URL` و`LIVEKIT_URL`
بعناوين النشر، واستخدم أسرار JWT وLiveKit خاصة بالخادم وبريد SMTP مناسبًا.

النسخة الحالية لم تُنشر على نطاق عام. نجاح الاختبارات المحلية لا يثبت وصول
أجهزة خارجية عبر شبكات الهاتف أو NAT؛ تحقق من جلسة ناشر ومشاهد خارج شبكة
الخادم بعد ضبط النشر. تبقى قاعدة البيانات ومفاتيح الإدارة خارج الوصول العام.

## الكود المحفوظ من المشروع السابق

تظل ملفات Flutter والمحاسبة والكتالوج والوثائق ذات المراحل الثماني محفوظة
كمصدر سابق. الواجهة الحالية تقتصر على اللايفات والحسابات والمشاهدة والمحادثة؛
تلك الملفات لا تعني تفعيل الهدايا أو شراء العملات أو سحب الأرباح في هذه النسخة.
